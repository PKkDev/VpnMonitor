# VpnMonitor

Мониторинг клиентов OpenVPN-сервера: кто подключён, с какой скоростью качает и когда подключался в последний раз.

## Как это устроено

| Проект | Что делает |
| --- | --- |
| `VpnMonitor.Service` | Консольный сервис на сервере с OpenVPN. Раз в 2 минуты запрашивает `status` у management-интерфейса и пишет в PostgreSQL снимок по каждому клиенту, почасовой трафик и отметку об опросе. |
| `VpnMonitor.WUI` | Клиент под Windows (WinUI 3). Читает данные из той же БД: клиенты, карточка клиента, статистика трафика, обзор сервера. Живёт в трее и присылает уведомления. |
| `VpnMonitor.Data` | Общая часть: сущности, `DataContext`, миграции EF Core, расчёт скорости и трафика. |
| `VpnMonitor.Tests` | Тесты парсера, чтения ответа OpenVPN, расчётов скорости и трафика и повторных попыток сервиса. |

### Что хранится в базе

| Таблица | Что в ней | Очистка |
| --- | --- | --- |
| `vpn-client` | Снимок каждого подключённого клиента при каждом опросе: счётчики байтов, время подключения, адреса. | Старше `RetentionDays`, кроме последнего снимка клиента. |
| `client-traffic-hourly` | Трафик клиента за каждый час (UTC): разница счётчиков между снимками одной сессии. | Не очищается: из неё строится статистика за любой срок. |
| `monitor-poll` | Каждый успешный опрос и число клиентов в нём, в том числе опросы без клиентов. | Старше `RetentionDays`. |
| `monitor-heartbeat` | Одна строка: время последнего опроса и версия OpenVPN. | — |

Клиент онлайн, если он был в последнем опросе и сервис опрашивал сервер не дольше 10 минут назад. Скорость — разница счётчиков байтов между двумя последними снимками сессии. Трафик последних минут перед отключением не учитывается: счётчики видны только при опросе.

## Приложение

- **Клиенты** — кто онлайн, сколько в сети, текущая скорость, когда подключался последний раз. Кружок слева вверху заполняется до следующего автообновления (раз в минуту); по нажатию данные обновляются сразу.
- **Карточка клиента** — открывается по нажатию на клиента. График скорости, трафик по часам или дням, история сессий и адреса, с которых клиент подключался, за 24 часа, 7 или 30 дней.
- **Трафик** — сколько скачано и отдано за сегодня, 7 или 30 дней и за всё время, по дням и по клиентам.
- **Сервер** — состояние сервиса и версия OpenVPN, графики числа клиентов онлайн и суммарной скорости, трафик.

Скорость показывается в Кбит/с и Мбит/с (1 Мбит/с = 1 000 000 бит/с), объём — в КБ, МБ и ГБ (1 МБ = 1024 КБ).

Закрытие окна не завершает приложение: оно остаётся в трее, продолжает обновлять данные и присылает уведомления Windows, когда клиенты подключаются или отключаются и когда сервис перестаёт присылать данные. Открыть окно — щелчок по значку в трее, выйти — пункт «Выход» в его меню. Повторный запуск приложения показывает уже открытое окно.

## Требования

- .NET SDK 8 или новее
- PostgreSQL
- OpenVPN с включённым management-интерфейсом (без пароля), по умолчанию ожидается `127.0.0.1:7505`:

  ```
  management 127.0.0.1 7505
  ```

- Для `VpnMonitor.WUI` — Windows 10 1809+ и Visual Studio 2022 с нагрузкой «Разработка приложений WinUI»

## Настройка

Скопируйте `appsettings.Example.json` под именем `appsettings.Private.json` в папки `VpnMonitor.Service` и `VpnMonitor.WUI` и впишите строку подключения. Файл в git не попадает.

| Параметр | По умолчанию | Значение |
| --- | --- | --- |
| `NpgSql:ConnectionString` | — | Строка подключения к PostgreSQL. |
| `Monitor:Host` | `127.0.0.1` | Адрес management-интерфейса OpenVPN. |
| `Monitor:Port` | `7505` | Порт management-интерфейса. |
| `Monitor:IntervalSeconds` | `120` | Пауза между опросами. |
| `Monitor:RetryDelaySeconds` | `10` | Пауза перед повтором после неудачного опроса. |
| `Monitor:RetentionDays` | `30` | Сколько дней хранить снимки. `0` отключает очистку. |

Секция `Monitor` нужна только сервису и может отсутствовать целиком.

## База данных

Схема ведётся миграциями EF Core. Сервис применяет их сам при запуске, поэтому пользователю БД нужны права на создание таблиц и индексов. Если таблица `vpn-client` уже существует (создана до появления миграций), она остаётся как есть.

Команды `dotnet ef` запускаются через проект сервиса: контекст и строка подключения берутся из его DI и `VpnMonitor.Service/appsettings.Private.json`. Один раз после клонирования:

```bash
dotnet tool restore
```

Новая миграция после изменения сущностей:

```bash
dotnet ef migrations add ИмяМиграции --project VpnMonitor.Data --startup-project VpnMonitor.Service
```

Применить миграции вручную, не запуская сервис (к базе из `appsettings.Private.json`):

```bash
dotnet ef database update --project VpnMonitor.Data --startup-project VpnMonitor.Service
```

Раз в сутки сервис удаляет снимки и опросы старше `RetentionDays`. Последний снимок каждого клиента сохраняется всегда, чтобы клиент не пропадал из списка и была видна дата его последнего подключения.

Миграция `AddTrafficStatistics` переводит счётчики байтов из текста в `bigint` и заполняет почасовой трафик и историю опросов из накопленных снимков. На большой таблице она может идти несколько минут. Приложение рассчитывает на новую схему, поэтому сначала обновите сервис: до этого приложение покажет подсказку «База данных ещё не обновлена».

## Запуск

Сервис:

```bash
dotnet run --project VpnMonitor.Service
```

Публикация сервиса одним файлом под Linux:

```bash
dotnet publish VpnMonitor.Service -c Release -r linux-x64 --self-contained -p:PublishSingleFile=true -o publish
```

Рядом с исполняемым файлом должен лежать `appsettings.Private.json`.

При потере связи с OpenVPN или БД сервис не завершается: пишет ошибку в лог и повторяет попытку через `RetryDelaySeconds`, заново открывая соединение. По SIGTERM и Ctrl+C останавливается штатно. Сам процесс всё же стоит запускать под systemd с `Restart=always` — на случай падения и для автозапуска после перезагрузки.

Клиент запускается из Visual Studio (проект `VpnMonitor.WUI`, платформа x64, профиль «Package») — приложение работает как MSIX-пакет: так регистрируются уведомления. Сборка из консоли:

```bash
dotnet build VpnMonitor.WUI -p:Platform=x64
```
